# Domain docs

## Layout

Single-context: `GLOSSARY.md` at the repository root and ADRs
under `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and the ADRs relevant to the area being explored.

If these documents do not exist, proceed silently.
The domain-modeling skill creates them when terms or decisions
are resolved.

## Vocabulary

Use the glossary's terms when naming domain concepts in issues,
proposals, hypotheses, and tests.

If a concept is missing, reconsider whether it belongs to the
domain or record the gap for domain-modeling.

## Decisions

When proposing something that contradicts an existing ADR,
identify the ADR and explain why its decision should be revisited.
